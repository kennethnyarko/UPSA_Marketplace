# Accessibility foundation

Every screen and interaction should meet these baseline practices:

- Use semantic HTML landmarks and a logical heading hierarchy.
- Make all actions available by keyboard and show a visible `:focus-visible` indicator.
- Associate persistent labels with form controls; do not rely on placeholders as labels.
- Explain validation errors in text and associate them with the relevant input.
- Announce important loading, success, pending, and error state changes to assistive technology.
- Use buttons for actions and links for navigation; communicate disabled states clearly.
- Check text, controls, and focus indicators for sufficient contrast in their actual contexts.
- Do not communicate status through color alone; pair badges/colors with clear text or an icon plus text.
- Respect zoom and reflow at mobile widths; avoid requiring horizontal scrolling for ordinary page content.
- Provide meaningful image alternatives when listing images are implemented; decorative images use empty alt text.

Accessibility is part of feature acceptance and code review, not a final polish task.
